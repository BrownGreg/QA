# TP QA - Présentation du projet

Ce dépôt propose une série de travaux pratiques (TP) autour de l’assurance qualité, organisés en cinq volets :

1. **TP1 : Test fonctionnel et bug bash**
2. **TP2 : Stratégie de vérification ISO/IEC 25010**
3. **TP3 : Automatisation de tests avec Selenium IDE**
4. **TP4 : Tests de non-régression et rapport de test**
5. **TP5 : Assurance Qualité pour votre modèle IA**

---

## TP1 : Test fonctionnel et Bug Bash sur Leboncoin

**Objectifs** :
- Prendre une application existante (Leboncoin)
- Faire un bug bash
- Produire un diagramme de séquence et un diagramme d’activité (PNG dans `TP1/diagrams`)
- Écrire un scénario de test vertical et un scénario de test horizontal (`TP1/tests`)
- Créer une branche `staging`
- Documenter les bugs sous forme de GitHub Issues
- **Bonus** : Intégrer un outil d’automatisation de tests (Playwright E2E via GitHub Actions)

---

## TP2 : Stratégie de vérification ISO/IEC 25010

**Objectifs** :
- Analyser chaque critère du modèle ISO/IEC 25010 (fonctionnalité, fiabilité, sécurité, utilisabilité, performance, etc.)
- Proposer une stratégie de test pour chaque critère
- Définir des métriques ou méthodes de vérification


---

## TP3 : Automatisation de tests avec Selenium IDE

**Objectifs** :
1. Reprendre le scénario de test vertical de TP1
2. Enregistrer le flux via **Selenium IDE**
3. Capturer chaque étape (screenshots)
4. Exporter les captures en **PDF**


---

## TP4 : Tests de non-régression et rapport

**Objectifs** :
1. Proposer un test de non-régression (e.g., smoke test) et définir quand le lancer (processus en 5 étapes)
2. Rédiger un rapport de test basé sur les bugs et scénarios TP1-TP3
3. Décrire les types de feedback souhaités et donner des exemples
4. Produire un exemple de code en TDD avec captures d’étapes



## TP5 : Assurance Qualité pour votre modèle IA

**Objectifs** :
1. Proposer une stratégie QA adaptée à votre projet IA (tests unitaires, d’intégration, fonctionnels, performance, robustesse)
2. Mettre en place et exécuter cette stratégie (scripts, notebooks, CI/CD)
3. Appliquer chaque concept de QA à votre modèle (coverage, validation des jeux de données, KPI de performance)
4. Conceptualiser un flow de feedback via chatbot pour collecter la note utilisateur (1–5)
5. Évaluation de notre IA avec des KPI pertinents (perplexité, cohérence, taux de réponses correctes, satisfaction utilisateur)
